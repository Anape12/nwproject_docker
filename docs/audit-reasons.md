# 認証監査ログの理由

`V25__add_audit_reason_catalog.sql` で `audit_reason_mst` を作成し、`audit_log` に `reason_code` と `detail_data` を追加します。理由文言は監査分類と理由コードの組で管理します。認証処理は `Outcome` 名（例: `BAD_PASSWORD`）を理由コードとして保存し、失敗回数やロック解除予定時刻を JSON データとして保存します。ソースには利用者向けの監査理由文言を持たせません。

監査ログ画面は検索時に `audit_reason_mst.message_template` を参照し、`{failedCount}` と `{lockUntil}` を記録時の値で置換して表示します。V25 より前のログは従来の `detail` 欄を表示するため、履歴を移行・削除する必要はありません。理由コードに対応するマスタ行がない場合は、監査ログ画面にコードを表示します。

マスタ文言を変更すると過去ログの表示も変わります。過去の表示文言そのものを固定する要件が生じた場合は、記録時の文言を別途スナップショットとして保存してください。`Outcome` 名は保存済みデータのキーになるため、名称変更時にはマイグレーションが必要です。
